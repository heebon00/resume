다만 **레이아웃상 위험 1건**과, 이번 변경 때문에 실제 문제로 드러난 **기존 결함 1건**이 있다.

## 2. 이상 없음으로 확인된 것

| 항목 | 확인 방법 | 결과 |

| `top-1/2` 유틸 생성 | 빌드 CSS 검사 | `.top-1\/2{top:50%}` 생성됨 |
| `-translate-y-1/2` 유틸 생성 | 빌드 CSS 검사 | `--tw-translate-y:calc(calc(1 / 2 * 100%) * -1)` 생성됨 |
| `--tw-translate-x/y` 초기값 | 빌드 CSS 검사 | `@property ... initial-value:0` 등록됨 → `translate` 선언이 무효화되지 않음 |

| 빌드 | `npm run build` | 성공 (기존 chunk 크기 경고만) |

## 3. 실측 좌표 (1920 캔버스 디자인 단위 기준)

```
사진 박스   x  468.0 ~ 1453.0   y 221.0 ~ 888.0
카피 h1     x 1461.5 ~ 1845.0   y 396.5 ~ 491.5   (폭 383 · 높이 95)
```

- 변경 전(`top:122`): 카피 y 122~217 → 사진 y 221 보다 위. **세로로 안 겹침**
- 변경 후: 카피 y 396~491 → 사진 y 221~888 안쪽. **세로로 완전히 겹침**

## 4. 위험 1 — 사진과의 가로 여백이 8.5u 뿐이다

세로가 겹치게 되면서, 사진과 카피를 갈라놓는 것은 이제 **가로 여백 8.5u**(1453 → 1461.5)
하나뿐이다. 1920px 화면에서 약 8.5px, 1280px 화면에서 약 5.7px 이다.

원래 코드 주석은 이 전제를 명시하고 있었다 —
> “사진과 Y축이 안 겹치니 가로 위치는 자유롭다”

이번 변경이 그 전제를 깼는데, 주석은 그 문장을 지우면서 새 전제(가로 8.5u 가 유일한
안전거리)는 남기지 않았다.

영향: 웹폰트(`font-display`) 로딩이 실패해 폴백 서체로 그려지거나, 카피 문구가 한 글자라도
길어지면 카피가 곧바로 사진 위로 올라탄다. 변경 전에는 세로로 떨어져 있어 이런 변화가
배치를 깨뜨리지 않았다.

## 5. 위험 2 — `redLines[0]` 의 꼬리 공백 12칸 (기존 결함, 이번 변경으로 표면화)

`src/content/portfolio.js:61`
```js
redLines: ["맡은 임무는            ", "책임감을"],
// 주석: "가운데 정렬이라 이 공백이 글자를 왼쪽으로 당기며, 빼면 위치가 어긋난다."
```

**주석의 전제와 현재 코드가 어긋나 있다.** h1 은 `text-right` 다(이번 변경 이전부터).
그리고 `Letters` 컴포넌트가 글자를 `inline-block whitespace-pre` 로 하나씩 쪼개므로,
이 꼬리 공백들은 접히지 않고 **실제 폭을 가진 박스 12개**로 남는다.

실측 결과:

| | 현재 | 꼬리 공백 제거 시 |
|---|---|---|
| h1 폭 | 383u | 288u |
| h1 왼쪽 끝 | 1461.5 | 1556.9 |
| 사진과의 여백 | **8.5u** | **103.9u** |
| “맡은 임무는” 줄 오른쪽 끝 | 1705.5 | 1845.0 |
| “좋아하는 일은” 줄 오른쪽 끝 | 1845.0 | 1845.0 |

즉,
1. 두 구간의 오른쪽 정렬선이 **139.5u 어긋나 보인다**. 자리 교체 연출에서 첫 구간은 오른쪽
   끝에 딱 붙는데 둘째 구간은 안쪽으로 쑥 들어간다.
2. 이 보이지 않는 공백이 h1 폭을 95u 부풀려 **4번의 안전 여백을 거의 다 잡아먹는다.**

## 6. 선택지 (조치 전 승인 필요)

원인은 확인됐지만, 어느 쪽이 요청 의도인지는 **확인 안 됨**이라 임의로 고르지 않았다.

- **A. 그대로 둔다.** 지금도 겹치지는 않는다. 폰트 폴백 위험만 감수한다.
- **B. 꼬리 공백만 제거** (`redLines[0]` → `"맡은 임무는"`, 관련 주석도 갱신).
  두 구간 오른쪽 정렬이 맞고, 사진과의 여백이 8.5u → 103.9u 로 벌어진다.
  → 다만 “맡은 임무는” 줄이 오른쪽으로 139.5u 이동하므로 **보이는 배치가 바뀐다.**
- **C. 공백은 두고 `right` 값만 키운다** (예: `right: 75` → `right: 40` 쪽으로 조정).
  글자 위치를 유지한 채 여백만 확보하지만, 근본 원인(유령 공백)은 남는다.
- **D. 카피를 사진 위쪽으로 되돌린다** (변경 취소).
