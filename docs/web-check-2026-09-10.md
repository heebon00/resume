## 5 - 접근성

이력서 페이지는 **100점**이며 지적 항목이 없다.
메인은 **96점**이고, 깎인 두 항목이 **모두 헤더 로고 하나에서 나온다.**

### 5-1. 글자 색 대비 1.53 (기준 4.5 미만)

```
<span class="brand-mark-text …">HEEBON</span>
전경 #D4183D (크림슨)  /  배경 #505050 (회색)
15px · bold  →  대비 1.53 : 1   (필요 4.5 : 1)
```

로고 색은 참고 이미지에서 스포이트로 딴 값을 그대로 쓴 것이다(`src/index.css` 의
`brand-mark-bg` · `brand-mark-text`). 어두운 회색 위에 어두운 크림슨이라 글자가
거의 읽히지 않는 수준이다.

### 5-2. 눈에 보이는 글자와 접근성 이름이 다르다

```
<a href="#m-hero" aria-label="맨 위로">  … 안에 "HEEBON" 이 보인다
```

화면에는 "HEEBON" 이 보이는데 화면 낭독기에는 "맨 위로" 로 읽힌다. 음성으로
조작하는 사용자가 "HEEBON" 이라고 말해도 이 링크가 잡히지 않는다
(WCAG 2.5.3 Label in Name).

### 두 항목이 이번에 새로 잡힌 이유

**2026-09-10 이전에는 모바일 헤더 로고가 파비콘 이미지(`favicon-bon.png`)였다.**
글자가 없으니 대비 검사도, 이름 불일치 검사도 걸리지 않았다. 이번에
"데스크톱과 모바일 로고를 똑같이 해 달라"는 요청으로 `BrandMark` 를 모바일에도
넣으면서(커밋 `6512cd0`) 두 항목이 드러났다.

즉 **데스크톱에는 원래 있던 문제**이고, 모바일로 옮겨오면서 검사에 잡힌 것이다.
로고를 되돌리자는 뜻이 아니라, 로고 자체를 고쳐야 두 화면이 함께 해결된다.

### 조치 — 적용 완료 (커밋은 아래 9장)

처음 적은 조치안의 대비값이 손계산이라 틀렸다. 실제로 재 보니 **글자만 밝혀서는
기준을 못 넘긴다.** 배경 `#505050` 을 그대로 두면 글자가 크림슨이 아니라
연분홍까지 가야 한다.

| 글자 | 배경 | 대비 | 판정 |
| --- | --- | --- | --- |
| `#D4183D` | `#505050` | 1.53 | 원래 조합 · 미달 |
| `#FF5A78` | `#505050` | 2.68 | 글자만 밝혀서는 모자란다 |
| `#FF7D91` | `#505050` | 3.30 | 큰 글씨 기준(3.0)만 통과 |
| `#FFB3C1` | `#505050` | 4.79 | 통과하지만 크림슨이 아니라 연분홍이 된다 |
| **`#FF5A78`** | **`#2A2A2A`** | **4.77** | **통과 · 크림슨 유지 → 채택** |

글자를 한 단계 밝히고 배경을 한 단계 어둡게 해서, "어두운 상자에 크림슨 글자"
라는 인상은 그대로 두고 기준만 넘겼다. 밝힌 크림슨은 `--color-brand-mark` 라는
전용 토큰으로 두었다 — 기존 `--color-tag-crimson`(#D4183D)은 키워드 태그 등
다른 곳에서 쓰므로 건드리지 않는다. 점선도 글자와 같은 색으로 따라간다.

5-2 는 `aria-label="맨 위로"` 를 **`aria-label="HEEBON — 맨 위로"`** 로 바꿔
해결했다. 눈에 보이는 글자가 접근성 이름 안에 들어가므로 음성 조작에서
"HEEBON" 으로도 이 링크가 잡힌다. 데스크톱·모바일 두 곳 모두 적용했다.
