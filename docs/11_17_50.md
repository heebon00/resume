## 원인 — 실측으로 확인됨

- 한 컷(`.pfr-stage`)은 **화면 전체 높이(100vh)** 를 기준으로 위 여백 `7vh` · 아래 여백 `5vh`
  안에 내용을 채운다. 네비 바가 위를 덮는다는 것이 이 계산에 없다.
- 1920 × 950 에서 위 여백 7vh 는 66.5px 인데 네비 바는 86.4px 이다. 차이 약 20px 만큼 제목이 가려진다.
- 두 값 모두 **네비 바가 지금보다 낮던 때 기준**이다.
  - `index.css` 의 `.pfr-index` 주석: "고정 GNB 바(높이 66)" — 그 뒤 로고 상자가 생기며 바가 커졌다
    (`Hero.jsx` 주석에도 "66 → 실측 93u" 로 남아 있다).
- **내용은 이미 화면을 꽉 채운 상태다.** 윗줄 제목 위 끝이 위 여백 끝(66.7 ≈ 66.5)에,
  아랫줄 제목 아래 끝이 아래 여백 끝(902.7 = 950 − 47.5)에 딱 붙어 있고, 이미지가 줄어들어(flex-shrink)
  자리를 맞추고 있다. 표 오른쪽 열의 여유 36~47px 은 빈 자리가 아니라 **아래 여백 5vh** 다.
  → 내용을 그냥 내리면 아래가 잘리고, 위 여백을 늘리면 **그만큼 이미지가 작아진다.**

네비 바 높이는 로고 쪽이 정한다(메뉴 글자 쪽보다 높다):
`a py-16(32u) + BrandMark py-13(26u) + gap-4 × 2(8u) + 점 3px × 2 + 글자 15px` = **66u + 21px**
(1920 에서 86.5 · 실측 86.4, 1440 에서 70.5 · 실측 69.9).

## 선택지별 조치안

**A. 위 여백을 네비 바 높이 + 여유로 바꾼다**
- `.pfr-stage` 위 여백 `7vh` → `네비 바 높이(66u + 21px) + 여유 16u`, `.pfr-index` 의 `top` 도 같은 기준으로
- 결과: 제목·번호가 바 아래로 내려온다. 대신 이미지가 줄어든다
  (1920×950 에서 약 393 → 357px, 1536×730 에서 약 297 → 262px — 계산값, 적용 후 실측 필요)
- 단점: 바 높이를 식으로 적어 두므로 로고 크기를 다시 바꾸면 이 식도 함께 고쳐야 한다
  (MY SKILLS 때처럼 JS 로 바 높이를 재서 CSS 변수로 넘기면 이 걱정은 없다 — 코드가 조금 늘어난다)

**B. A + 아래 여백을 줄여 이미지가 덜 줄게 한다** (권장)
- A 에 더해 아래 여백 `5vh` → `3vh`
- 1920×950 에서 아래 여백 47.5 → 28.5px, 되찾은 19px 만큼 이미지가 덜 준다(약 393 → 376px)
- 단점: 아랫줄 제목(EDITOR & DIRECTOR · REDESIGN)이 화면 아래 끝에 조금 더 가까워진다

**C. 제목 두 줄 크기를 줄인다** (디자인 변경)
- `--pfr-title-size: min(14vh, 148u)` → 예 `min(12vh, …)`. 제목 두 줄 높이가 약 39px 줄어 이미지 크기를
  지키면서 위 여백을 늘릴 자리가 난다
- 단점: 큰 제목의 인상이 약해진다

**D. 이 구간에서만 네비 바를 숨긴다** — 동작이 바뀌고 메뉴를 못 쓰게 되어 비권장

→ **권장: B.** 제목 크기와 네비 바 동작은 그대로 두고, 이미지가 조금만 작아진다.

### 모바일 선택지

**M1. 위 여백을 헤더 높이 + 여유로** (데스크톱과 같은 방식, 모바일 헤더도 실측)
- 번호 · 윗줄 제목이 헤더 아래로 내려온다. 대신 늘어난 만큼(375×560 에서 약 23px) **이미지가 줄어든다** (58 → 약 35px)

**M2. M1 + 제목을 줄여 이미지를 지킨다** (데스크톱 C 와 같은 방식)
- 이미지 크기 유지. 대신 375×560 에서 제목 한 줄 37 → 약 26px (약 30% 작아짐)

**M3. M1 + 설명 표 안 간격을 줄여 자리를 만든다**
- 이미지 · 제목 크기 유지. 표의 줄 사이 · 위아래 여백만 좁힌다. 얼마나 줄일지는 실측하며 정한다

→ **권장: M3.** 이미지가 더 중요하다는 방향과 맞고, 모바일에서 가장 큰 덩어리를 줄인다.
