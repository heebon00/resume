## 원인 — 실측으로 확인됨

어제 커밋 `23b4244` "글자 최소 16px 보장" 에서 생겼다.

- 이 사이트는 모든 크기가 `--u`(화면 폭 비례 단위)라 화면이 좁아지면 **카드·도넛·글자가 같이 줄어드는** 구조다.
- 그 커밋에서 **글자에만** `max(16px, …)` / `max(18px, …)` 바닥을 걸었다.
  → 1440 · 1280 에서 **카드 상자(높이 244u)와 도넛(64u)은 계속 줄어드는데 글자는 안 줄어서** 넘친다.
- 모바일은 도넛 44u(=44px) 는 그대로인데 가운데 숫자가 11u → 16px 로 커져서 구멍보다 넓어졌다.
  설명은 글자만 12u → 16px 로 올리고 줄 높이 `17u` 는 그대로 둬서 붙었다.
- 그 커밋의 검증 항목은 "16px 미만 글자 0건 · 가로 스크롤 없음" 이었고,
  **카드 안에서 넘치는지는 검사 항목에 없었다.**

## 선택지별 조치안

문제가 두 갈래라 나눠서 적는다. 메모리 규칙대로 **하나씩** 적용하고 확인받는다.

### ① 데스크톱 1280~1919 — 카드 밖으로 넘침

**A. 카드 안 글자만 16px 바닥에서 뺀다** (버튼을 뺐던 것과 같은 방식)
- 수정: `SkillCard.jsx`, `SkillDonut.jsx` 의 글자 크기를 `--u` 비례로 되돌림
- 장점: 시안 비율 그대로, 수정 2 파일, 다른 섹션 영향 없음
- 단점: 1440 에서 카드 글자가 12~13px 로 내려간다 → **"어떤 화면에서도 16px 미만 금지" 요청과 충돌**

**B. 16px 유지, 카드 높이를 글자에 맞춰 늘린다**
- 수정: `Skills.jsx`(행 높이·2행 위치·섹션 배경 높이) + 그 아래로 줄줄이 밀리는
  `Footer.jsx`(top 5827 · 5947) + `App.jsx`(`CANVAS_H = 6077`, 창2 계산에도 쓰임)
- 이 좌표들이 전부 `--u` 고정값이라 "좁은 화면에서만 추가로 늘어나는 높이" 를 식으로 넣어야 한다
- 장점: 16px 규칙과 시안 배치 모두 유지
- 단점: 수정 범위가 크고 푸터·연락처 위치까지 건드린다. 스크롤 연출(창2)과 맞물리는지 추가 확인 필요

**C. 16px 유지, 카드 안을 압축한다** (디자인 변경)
- 예: 1920 미만에서 도넛+라벨을 이름 줄 오른쪽으로 올리기, 아이콘 줄 없애기 등
- 장점: 카드·섹션 크기는 그대로라 푸터 영향 없음
- 단점: 시안과 모양이 달라진다. 구체 배치는 따로 정해야 함

→ **권장: B.** 16px 요청을 지키면서 모양도 안 바뀐다. 다만 손이 커서, 작게 끝내고 싶으면 A.

### ② 도넛 가운데 숫자가 링을 덮음 (1440 · 1280 · 모바일)

**D1. 도넛에 px 바닥을 건다** — 예: 데스크톱 `max(52px, 64u)`, 모바일 44 → 52
- 구멍이 37px 이상 → 16px 숫자(최대 36px)가 들어간다
- 단점: 모바일 카드 안쪽 폭 139px 에 도넛 52 + 간격 8 + "Proficiency" 약 80px = 140px 로 빠듯함.
  데스크톱은 도넛이 커지는 만큼 ① 의 넘침이 조금 더 커진다

**D2. "%" 기호만 작게** — 숫자 16px 유지, `%` 는 0.6em
- 숫자 폭이 약 28px 로 줄어 구멍(30~34px)에 들어간다
- 단점: `%` 한 글자는 16px 미만이 된다 (규칙 예외로 둘지 결정 필요)

**D3. 숫자만 16px 바닥에서 뺀다** — 도넛과 같이 비례로 줄어듦
- 단점: 1440 에서 13px

→ **권장: D1**, 모바일 폭이 빠듯하면 D2 병행.

### ③ 모바일 설명 줄 간격 (작은 것)
