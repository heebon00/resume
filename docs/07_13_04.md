# 연락처 폼(ContactUs) 캡챠 확인 결과 — 현재 전송 불가 상태

작성: 2026-09-07 13:04 (KST)
대상: `src/components/ContactUs.jsx` (커밋 `d2dfeef`, 이미 origin/main에 푸시됨)

---

## 1. 무슨 일이 있었나

"폼에 캡챠가 걸려 있는지" 실제 전송으로 확인했다.
Chrome 확장이 연결되지 않아 브라우저 자동화는 못 썼고, 대신 EmailJS REST API를
브라우저와 동일한 형태(`Origin: http://localhost:5173`)로 직접 호출했다.

요청:

```
POST https://api.emailjs.com/api/v1.0/email/send
service_id=service_vn90mig / template_id=template_g2gie6l / user_id=Y5XuRsa-hEXGt1Gic
```

응답:

```
HTTP/1.1 400 Bad Request
reCAPTCHA: The g-recaptcha-response parameter not found
```

## 2. 현재 상태 (확인된 사실)

- **캡챠 있음.** EmailJS 템플릿 `template_g2gie6l`에 reCAPTCHA V2 검증이 **켜져 있다.**
- **폼은 지금 항상 실패한다.** 페이지의 폼에는 reCAPTCHA 위젯이 없어
  `g-recaptcha-response` 값을 만들 수 없고, 서버가 400으로 거절한다.
  사용자에게는 "전송에 실패했습니다."만 보인다.
- 코드 쪽에도 캡챠 흔적이 전혀 없다 — `ContactUs.jsx` 어디에도
  reCAPTCHA 스크립트/위젯/필드가 없다.
- 추가로, EmailJS 문서 기준 **reCAPTCHA는 `emailjs.send`에서만 동작하고
  `emailjs.sendForm`에서는 동작하지 않는다.** 현재 코드는 `sendForm`을 쓴다.

## 3. 영향 범위

- 데이터 손실 없음. 코드/저장소 손상 없음.
- 다만 **배포된 사이트에서 방문자가 보낸 메시지는 한 건도 도착하지 않는다.**
  (이미 origin/main에 푸시된 상태)
- 테스트 메일은 전송되지 않았다 (400으로 거절). 받은편지함에 테스트 메일 없음.

## 4. 추정 원인 (확정 아님)

EmailJS 템플릿을 만들 때 Settings 탭의
"Enable reCAPTCHA V2 verification"이 켜진 채로 저장된 것으로 보인다.
다만 대시보드를 직접 확인하지 못했으므로 **언제·왜 켜졌는지는 확인 안 됨.**

## 5. 조치안 (택 1 — 승인 필요)

### A안. 템플릿에서 reCAPTCHA 끄기 (가장 간단)
- EmailJS 대시보드 → Email Templates → 해당 템플릿 → Settings →
  "Enable reCAPTCHA V2 verification" 체크 해제
- 코드 수정 불필요. 지금 코드 그대로 동작하게 된다.
- 대가: 봇 스팸 방어가 없어진다. 대신 EmailJS 쪽
  Allowed Origins(도메인 제한) + 월 전송 한도로만 막게 된다.

### B안. 코드에 reCAPTCHA V2 위젯 붙이기 (방어 유지)
- Google reCAPTCHA 사이트키 발급 → 폼에 위젯 렌더 →
  토큰을 `g-recaptcha-response`로 넘기도록 `sendForm` → **`send`로 교체**
- 대가: 작업량이 있고, 폼 UI에 캡챠 박스가 추가된다.

### C안. 캡챠는 끄고 허니팟(honeypot)으로 대체
- 템플릿에서 reCAPTCHA 끄고, 숨김 입력칸에 값이 차면 전송을 막는 방식
- 대가: 캡챠보다 방어력은 약하지만 UI를 해치지 않고 코드 몇 줄로 끝난다.

## 6. 사용자에게 확인할 것

1. A / B / C 중 어느 쪽으로 갈지
2. B안이면 Google reCAPTCHA 사이트키를 발급해 주실 수 있는지
   (시크릿 키는 EmailJS 대시보드에 직접 입력하셔야 한다 — 저는 입력하지 않는다)
3. 수정 후 다시 실제 전송 테스트를 돌릴지

## 7. 처리 결과 (2026-09-07 마감)

**B안(코드에 reCAPTCHA V2 위젯 추가)으로 진행 — 승인받고 조치 완료.**

- 도입 방식: 새 의존성 없이 Google 스크립트를 직접 지연 로드
  (연락처 섹션이 화면에 다가올 때 IntersectionObserver 로 async 주입).
  첫 화면 성능을 지키기 위한 선택 — `index.html` 주석 및
  `docs/web-check-2026-09-03.md` 4장과 같은 이유다.
- `emailjs.sendForm` → `emailjs.send` 로 교체하고 `g-recaptcha-response` 를 함께 보낸다.
- 사이트키는 공개값이라 코드에 둔다. Secret Key 는 EmailJS 템플릿 Settings 에만 있다.

### 검증 기록

| 확인 | 방법 | 결과 |
|---|---|---|
| 캡챠 검증 켜져 있음 | 토큰 없이 API 호출 | 400 `The g-recaptcha-response parameter not found` |
| Secret Key 정상 등록 | 가짜 토큰으로 API 호출 | 400 `invalid-input-response` (키가 틀리면 `invalid-input-secret` 이 온다) |
| 도메인 등록 | 브라우저에서 위젯 확인 | 처음엔 "지원 도메인 목록에 없습니다" — 콘솔에서 저장 버튼 미클릭이 원인이었다 |
| 전 구간 동작 | 사용자가 직접 캡챠 체크 후 전송 | **메일 수신 확인** |

캡챠 체크는 봇 탐지를 통과하는 행위라 내가 대신 누르지 않았고, 마지막 단계는 사용자가 직접 확인했다.
