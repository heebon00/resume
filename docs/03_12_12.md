# 표절 검사 — 도구가 필요한가, 무엇을 검사할 것인가 (2026-09-03 12:12)

질문: "이 사이트 표절 테스트 같은 걸 해야 하는데, 스킬이 필요해? 찾아와야 해?"

---

## 1. 짧은 답

**설치된 스킬 중에는 없다.** 그리고 **대부분의 경우 스킬을 새로 가져올 필요도 없다.**
이 사이트에서 실제로 문제가 될 만한 지점은 외부 검사 도구가 아니라
**출처 추적(provenance)** 으로 잡히는 것들이고, 그건 저장소만 보면 확인할 수 있다.

---

## 2. 밖에 있는 도구들 (찾아본 결과)

### Claude Code 플러그인
- `plagiarism-review` (bgreenwell/claude-plugins) — 존재한다. 다만 **학술 "글쓰기"** 대상이다.
  Gemini 문체 분석 + 로컬 TF-IDF/n-gram + 웹 검증 + (선택) Copyleaks·Grammarly.
  설치: `/plugin marketplace add bgreenwell/claude-plugins` → `/plugin install plagiarism-review@bgreenwell-plugins`
  → **이 사이트에는 잘 안 맞는다.** 검사 대상이 논문·에세이 텍스트다.

### 코드 유사도 검사 서비스 (전부 외부·유료 성격)
| 도구 | 성격 |
|---|---|
| Codequiry | 대학용 코드 표절 검사. 65개 언어, 웹 전체 대조, 토큰·구조 분석 |
| Copyleaks Codeleaks | 100개 이상 언어. 원문·유사·의역까지 탐지 |
| codeplagiarismchecker.com | 스탠퍼드 **MOSS** 알고리즘 기반, 30개 이상 언어 |

**한계를 분명히 해둔다.** 이 도구들은 "제출물 여러 개를 서로 대조"하거나
"공개 코드와 대조"하는 데 강하다. 반면 **디자인·레이아웃 표절은 못 잡는다.**
이 사이트의 위험은 코드 문자열보다 **디자인 쪽에 있다.**

---

## 3. 도구 없이 지금 이미 보이는 것 세 가지

작업하면서 확인된 사실이다. 추정과 확인을 구분해서 적는다.

### (1) 피그마 시안이 상용 WordPress 테마 구조 그대로다 — **확인됨, 가장 큰 건**

피그마 노드 이름에 이런 것들이 그대로 남아 있다.

```
div.wpb_wrapper      div.vc_row      div.wpb_column
div.ld-fancy-heading h6.ld-fh-element  div.ld-container
div#vc_accordion_62ff67320b7cd
```

- `wpb_` / `vc_` 접두사 = **WPBakery Page Builder** (구 Visual Composer)
- `ld-` 접두사 = **LiquidThemes** 의 워드프레스 테마 요소.
  `ld-fancy-heading` 는 LiquidThemes 공식 문서에 **"Liquid Fancy Heading"** 요소로 나와 있다
  (Ave / HUB 테마)

즉 이 피그마 파일은 **직접 그린 시안이 아니라, 돌아가는 워드프레스 사이트를 통째로
피그마로 가져온 것**으로 보인다. `vc_accordion_62ff67320b7cd` 같은 **자동생성 해시 ID**
까지 남아 있는 건 손으로 그렸다면 나올 수 없는 흔적이다.

→ **레이아웃·섹션 구성·간격 체계가 상용 테마에서 온 것**이라면, 그게 이 사이트에서
가장 표절 판정을 받기 쉬운 부분이다. 코드 검사 도구로는 안 잡힌다.

### (2) 스크롤 연출 참고 = Codrops — **확인됨, 문제 없음**

`33.md`, `44.md` 에 적힌 참고 사이트:
- `tympanus.net/Development/OnScrollFilter/`
- `tympanus.net/Development/SlicedDualImageLayout/`

Codrops 데모는 **별도 명시가 없으면 MIT 라이선스**다 (공식 licensing 페이지 기준).
**상업적 사용 가능.** 다만 예의상 출처 표기를 해두면 깔끔하다.

→ 여기는 걱정 안 해도 된다.

### (3) 이미지·폰트 — **미확인, 확인 필요**

| 자산 | 상태 |
|---|---|
| `hero-portrait` · `about-portrait` | 본인 사진으로 보임 — 문제 없음 |
| `design-dubai-skyline` · `design-resort` · `design-dark-building` · `gallery-greenhouse` 등 | **출처 확인 안 됨.** 스톡 사진이라면 라이선스 확인 필요 |
| `project-ikea-mockup` · `project-youtube-music-mockup` | **IKEA · YouTube Music 은 실제 기업 브랜드다.** 학습용 리디자인이면 "비공식 컨셉 작업"임을 명시해야 안전하다 |
| Pretendard · Paperlogy · Google Fonts 8종 | 대체로 자유 라이선스지만 **개별 확인은 아직 안 했다** |

## 4. 그래서 뭘 하면 되나 — 목적에 따라 갈린다

무엇을 위한 표절 검사인지에 따라 필요한 게 완전히 달라진다.

| 목적 | 필요한 것 |
|---|---|
| **학교·부트캠프 제출** (검사기를 통과해야 함) | 외부 서비스 필요. Codequiry / Copyleaks 유료 결제 — 내가 대신 돌릴 수는 없다 |
| **포트폴리오 공개 · 취업용** (문제 소지 없애기) | **도구 불필요.** 위 3장을 끝까지 추적해 출처 목록과 위험도를 정리하면 된다 |
| **클라이언트 납품 · 상업적 사용** | 라이선스 감사. 폰트·이미지·테마 각각 사용 조건 확인 |
| **텍스트 문구 표절만** | `plagiarism-review` 플러그인이 맞다. 설치하면 된다 |

---

## 5. 확인 부탁

1. 위 넷 중 어떤 목적인가?
2. **포트폴리오·취업용**이면 도구 없이 바로 진행하겠다 —
   이미지 EXIF·역검색, 폰트 라이선스, 피그마 시안 원본 테마 특정,
   코드에 남은 테마 흔적 정리까지 해서 **위험도별 목록**을 만들어주겠다.
3. **제출용 검사기 통과**가 목적이면 어떤 검사기를 쓰는지 알려달라.
   그 도구가 무엇을 보는지에 맞춰 코드를 정리하는 건 도와줄 수 있다.
