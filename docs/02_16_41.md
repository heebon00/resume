# public/favicon.svg — 확장자와 실제 형식 불일치

작성 2026-09-02 16:41 · 조치 전 보고 (아직 아무것도 바꾸지 않음)

## 무슨 일이 있었나

`public/favicon.svg` 를 파비콘으로 적용하려고 파일을 열었더니 **SVG 가 아니라 PNG** 였다.

## 현재 상태 (측정값)

| 항목 | 값 |
|---|---|
| 파일 경로 | `public/favicon.svg` |
| 실제 형식 | PNG (시그니처 `89 50 4E 47` 확인) |
| 크기 | 512 x 512, 8bit RGBA(colortype 6), 7,208 bytes |
| 생성 도구 | PNG 텍스트 청크에 `Software: Figma` |
| index.html | `<link rel="icon" type="image/svg+xml" href="/favicon.svg" />` (이미 이 경로를 가리키고 있음) |
| 서버 응답 | `Content-Type: image/svg+xml` (로컬 preview 에서 확인) |

즉 **PNG 바이트를 SVG 라고 알려주며 내려보내는 상태**다. 대부분의 브라우저는
SVG 파서로 읽으려다 실패해 파비콘이 표시되지 않는다.

## 영향 범위

- 데이터 손실 없음. 파일은 온전하며 이미지도 정상이다.
- 영향은 파비콘 표시 하나뿐이고, 사이트의 다른 동작에는 영향이 없다.
- 확인 안 됨: 실제 브라우저 3종에서의 표시 여부는 배포 전이라 확인하지 못했다.
  (서버가 보내는 MIME 이 형식과 다르다는 사실까지만 확인했다)

## 추정 원인 (확정 아님)

피그마에서 PNG 로 내보낸 뒤 파일 이름만 `.svg` 로 바꾼 것으로 보인다.
피그마의 SVG 내보내기는 텍스트 파일이 나오므로, PNG 시그니처가 있다는 것은
SVG 로 내보낸 파일이 아니라는 뜻이다. 다만 어느 단계에서 바뀌었는지는 확인되지 않았다.

## 선택지별 조치안

### A. `favicon.png` 로 복사하고 index.html 이 그 파일을 가리키게 한다 (권장)

- 원본 `favicon.svg` 는 손대지 않는다 (파일 개명 금지 규칙 준수)
- `public/favicon.png` 추가, `<link rel="icon" type="image/png" href="/favicon.png" />` 로 수정
- 장점: 즉시 적용, 원본 보존, 512x512 면 파비콘·홈 화면 아이콘 모두 충분
- 단점: 같은 이미지가 두 벌 남는다 (총 14KB)

### B. 파일 이름을 `favicon.png` 로 변경한다

- A 와 결과는 같고 중복 파일이 없다
- 기존 파일 개명이라 승인이 필요하다

### C. 피그마에서 진짜 SVG 로 다시 내보내 덮어쓴다

- 장점: 벡터라 어떤 크기에서도 선명하고 용량이 가장 작다
- 단점: 사용자가 피그마에서 다시 내보내 주셔야 한다

2. (C 를 고르실 경우) 새 SVG 파일을 어디에 두실지
